# FOMS Backend (รวมต้นแบบของตูน + schema กลางของทีม)

โค้ดชุดนี้รวม "ต้นแบบที่รันได้" ของตูน (Auth, master-data, จอง, งานของฉัน) เข้ากับ schema กลางที่ทีมตกลงกัน
ใช้ชื่อ collection / ฟิลด์เดิมของต้นแบบให้มากที่สุด **หน้าเว็บเดิมไม่ต้องแก้** แล้วเพิ่มส่วนที่ขาดและแก้บั๊ก

## วิธีใช้
```bash
npm install
cp .env.example .env     # แก้ MONGO_URI และตั้ง JWT_SECRET เอง
npm run seed             # ใส่ข้อมูลทดสอบ (ถ้าฐานข้อมูลยังว่าง ไม่ล้างข้อมูลเดิม)
npm start                # http://localhost:5000
npm test                 # ทดสอบ API 17 รายการ (ใช้ฐานข้อมูล foms_test แยกต่างหาก)
npm run test:db          # ทดสอบ unique index
```
**ถ้ามีงานจองเก่าอยู่ใน DB แล้ว** ให้รัน `npm run backfill` หนึ่งครั้ง เพื่อสร้างการล็อกศาลารายคืนให้งานเก่า

### รวมเข้ากับโปรเจกต์เดิมของท่าน
- ไฟล์ที่ **ทับของเดิม:** `models/User.js`, `models/FuneralModels.js`, `controllers/authController.js`, `routes/authRoutes.js`, `routes/bookingRoutes.js`, `config/db.js`
- ไฟล์ **ใหม่:** `middleware/auth.js`, `models/*` (ที่เหลือ), `utils/dates.js`, `seed/masterData.js`, `scripts/*`, `test/*`, `app.js`, `server.js`
- ต้องมีแพ็กเกจ: `express cors cookie-parser mongoose bcryptjs jsonwebtoken dotenv`
- `app.js` / `server.js` เป็นตัวอย่างการตั้งค่า (ไม่เห็น server.js เดิม) ถ้ามีของเดิมแล้วให้เทียบ: ต้องมี `cors({credentials:true})`, `cookieParser()` และต่อ route เป็น `/api/auth` กับ `/api`

## สิ่งที่แก้
| เรื่อง | ก่อน | หลัง |
|---|---|---|
| สมัครสองคนโดยไม่ใส่อีเมล | คนที่สองสมัครไม่ได้ (เงื่อนไข `email: null` ตรงกับทุกคนที่ไม่มีอีเมล) | สมัครได้ |
| จองโดยไม่ล็อกอิน | ได้ งานไม่มีเจ้าของ | 401 และ `hostId` มาจาก JWT เสมอ |
| ออกจากระบบ | หน้าเว็บส่ง POST แต่ route เป็น GET ได้ 404 | รับทั้ง POST และ GET |
| JWT | ออก cookie แต่ไม่มีที่ไหนตรวจ | `protect` / `restrictTo(...)` ใน `middleware/auth.js` |
| ดู/ยกเลิก/แนบสลิปงานคนอื่น | ทำได้ (เปลี่ยน hostId หรือ id ก็ได้) | 403 เฉพาะเจ้าของหรือ STAFF/ADMIN |
| จองศาลาซ้อนเมื่อกดพร้อมกัน | ผ่านทั้งคู่ | ล็อกรายคืน unique (hallId, date) ได้คนเดียว |
| จองต่อจากวันสุดท้ายของงานอื่น | ชนเพราะนับวันฌาปนกิจเป็นวันใช้ศาลา | จองได้ (ศาลาใช้ `nights` คืน) |
| ยกเลิก | ยกเลิกได้ทุกสถานะ ไม่คืนคิว | ยกเลิกได้เฉพาะ PENDING/CONFIRMED และคืนคิวศาลา |
| ตรวจข้อมูลจอง | ไม่ตรวจ (ผิดแล้ว 500) | 400 พร้อมข้อความ: คืน 1/3/5/7, แขก 1-1000, วันที่ไม่ย้อนหลัง, หมวดตัวเลือกละ 1 |
| รหัสผ่าน / เบอร์โทร | ไม่ตรวจความยาว / 081-234-5678 กับ 0812345678 ถือเป็นคนละเบอร์ | อย่างน้อย 8 ตัว / เก็บเป็นตัวเลขล้วน |
| role | `TEMPLE_STAFF`, `OPS_TEAM` | `STAFF`, `OPS` (ตามสัญญากลาง) |
| เลขงาน | สุ่ม (อาจซ้ำ) | รันต่อเนื่อง FOMS-2569-0001 |
| token | ส่งทั้งใน cookie และ body | cookie (httpOnly) เท่านั้น |

เพิ่ม `GET /api/auth/me` สำหรับเช็กเซสชันตอนเปิดหน้าเว็บ

## Schema: ของต้นแบบที่เก็บไว้ / ส่วนที่เพิ่ม
- **เก็บ:** ล็อกอินด้วยเบอร์โทร (อีเมลไม่บังคับ), `deceasedName`, บัญชีธนาคารของวัด, ราคาศาลาต่อคืน, `pdpaConsent`, ศาลาฝังในวัด, `Package`/`Addon`/`Booking` ชื่อและฟิลด์เดิม
- **เพิ่มใน Addon:** `categoryKey` (เช่น COFFIN, FLOWERS = เลือกได้ 1 ต่อหมวด), `categoryName`, `packageIds`, `isDefault` โดย `price` คือส่วนต่างราคา 0 = รวมในแพ็กเกจ, > 0 = อัปเกรด
- **เพิ่มใน Booking:** `paymentStatus` (UNPAID/SLIP_UPLOADED/PAID), `shareToken`, `rejectReason`, `cancelReason` และสถานะ `IN_PROGRESS`
- **Collection ใหม่:** `HallReservation` (ล็อกศาลารายคืน), `Person` (พระ/มัคนายก/พิธีกร), `PersonAssignment` (จัดรายคืน unique personId+date), `ScheduleItem`, `StepLog`, `Notification`, `TempleRule`, `Counter`
- **ไม่มี collection `Payment` แล้ว:** เก็บสถานะ/ไฟล์สลิปไว้ใน Booking (`paymentStatus`, `paymentSlipUrl`) หน้า ER ต้องแก้ตาม

## ยังไม่ได้แก้ (เป็นงานของเพื่อนตามบอร์ด ไม่ได้ลืม)
- สลิป: ยังตั้ง `status = PAID` ทันทีตามต้นแบบ เพื่อให้หน้าเว็บเดิมทำงาน **M4-07 (ธัชพล)** ต้องเปลี่ยนเป็น `SLIP_UPLOADED` แล้วให้เจ้าหน้าที่ตรวจ และอัปโหลดไฟล์จริง (ตอนนี้เก็บแค่ชื่อไฟล์)
- ยังไม่มี API ฝั่งเจ้าหน้าที่ (อนุมัติ/ปฏิเสธ, จัดพระ), กำหนดการ, แจ้งเตือน, สลับคิวเมื่อเปลี่ยนวัน → M3-xx, M4-06, M5-xx
- การคำนวณราคามีสูตรเดิมของต้นแบบ (ค่าศาลาต่อคืน + แพ็กเกจ + ค่าบริการต่อหัว + ตัวเลือก) ธัชพลเป็นเจ้าของสูตร (M4-01) ควรแยกเป็นฟังก์ชันกลางที่ทั้งหน้าเว็บและเซิร์ฟเวอร์ใช้ร่วมกัน ตอนนี้คำนวณซ้ำสองที่
- หน้าเว็บยังโชว์ตัวเลือกเป็นช่องติ๊กหลายอัน ควรเปลี่ยนเป็นเลือกหมวดละ 1 (เซิร์ฟเวอร์ตรวจแล้ว ถ้าติ๊กซ้ำหมวดจะได้ 400)
- หน้าเว็บยังไม่แสดงเลขบัญชีของวัด (`temple.bankName`, `temple.bankAccount`) ให้เจ้าภาพโอนเงิน
